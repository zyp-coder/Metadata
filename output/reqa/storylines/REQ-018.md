# REQ-018: MDM 主数据存活机制

**操作人员**：

| 角色 | 职责 | 参与步骤 |
|------|------|----------|
| 系统 | 拉数时逐字段比对、生成冲突项、应用修正保护 | 步骤2-4 |
| 数据管理员 | 冲突审查裁决、触发字段级回写 | 步骤5-7 |
| 业务人员 | 日常编辑档案（自动登记修正保护） | 步骤1 |

**用户旅程**：

1. **人工修正档案字段** - 操作者: 业务人员
   - 在档案详情/编辑抽屉修改字段值并保存
   - 系统自动登记该字段的修正保护标记（override：修正人/时间/原值），字段级血缘更新为「人工」

2. **同步拉数逐字段比对** - 操作者: 系统
   - sync-schema 拉数时不再整条覆盖，按主键匹配后逐字段比对源值与档案值
   - 值一致 → 跳过；值不一致 → 进入存活裁决

3. **存活裁决（三级规则，字段级）** - 操作者: 系统
   - 优先级：人工修正（override）> 源优先级 > 最新时间戳
   - 本期策略：**所有差异一律不自动覆盖**，规则仅用于在冲突项上生成「建议裁决」提示
   - 受修正保护的字段冲突项标记「修正保护」

4. **冲突项入队** - 操作者: 系统
   - 生成冲突项：档案/记录/字段/档案值/源值/源表/建议裁决/保护标记
   - 同一字段重复冲突只保留最新一条，旧项自动作废
   - 同步结果面板提示「本次产生 N 条冲突待审查」

5. **冲突审查裁决** - 操作者: 数据管理员
   - 档案详情页「冲突审查」Tab 查看待审查列表（可按字段/源表筛选、批量勾选）
   - 「接受源值」→ 档案字段更新为源值 + 版本快照 + 操作日志 + 解除该字段保护
   - 「保留档案值」→ 字段登记/维持修正保护，后续同步不再产生自动覆盖

6. **字段级回写源系统** - 操作者: 数据管理员
   - 「同步到数据源」重做为字段级两阶段：预检展示字段级差异清单 → 勾选字段 → 确认执行
   - 仅回写勾选字段到源表；失败字段明细进同步日志，不影响其他字段

7. **闭环追溯** - 操作者: 数据管理员/审计员
   - 字段级血缘可查：每个字段值来源（源表/人工/裁决）与更新时间
   - 冲突项全生命周期可查（待审查/已裁决-接受源/已裁决-保留/已作废）

**规则关注点**：

| 规则 ID | 适用步骤 | 违反处理 |
|---------|----------|----------|
| BR-018-1 | 步骤3 | 无源优先级配置 → 退化为时间戳优先（仅影响建议裁决） |
| BR-018-2 | 步骤2-4 | 差异字段自动覆盖 → 禁止，必须入冲突队列 |
| BR-018-3 | 步骤1 | 人工编辑未登记保护 → 视为缺陷 |
| BR-018-4 | 步骤5 | 裁决变更无版本快照 → 禁止提交 |
| BR-018-5 | 步骤6 | 记录级整条回写 → 禁止，必须字段级 |
| BR-018-6 | 步骤7 | 字段无血缘信息 → 首次同步补建 |

**依赖锚点**：

| 域 | 依赖类型 |
|------|----------|
| archive（sync-schema 拉数流程） | 改造依赖 — 覆盖逻辑重做为比对+入队 |
| archive（sync-to-source 回写流程） | 改造依赖 — 记录级重做为字段级两阶段 |
| archive（版本快照/操作日志） | 数据依赖 — 裁决变更留痕 |
| modeling（数据源/表元数据） | 数据依赖 — 源表标识、源优先级配置 |
