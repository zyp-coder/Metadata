# REQ-019: 角色权限与档案字段可见/可编辑控制（轻量故事线）

> 轻量版：多角色旅程。实体/状态机详细设计见 darc 设计日记。

**操作人员**：

| 角色 | 职责 | 参与步骤 |
|------|------|----------|
| 系统管理员 | 维护用户与角色，配置角色×档案域字段可见/可编辑 | 1-3、6 |
| 普通用户 | 在授权范围内浏览/维护档案 | 4-5 |

**用户旅程**：

1. 系统管理员用内置 admin 账号登录系统 - 操作者: 系统管理员
2. 在系统管理页新建角色（如「门店运营」），逐域勾选可见字段与可编辑字段（白名单） - 操作者: 系统管理员
3. 新建用户账号，分配一个或多个角色（多角色取并集） - 操作者: 系统管理员
4. 普通用户登录；未登录访问任何页面被重定向登录页 - 操作者: 普通用户
5. 打开档案列表/详情：仅可见字段呈现（后端不下发隐藏字段）；编辑时仅可编辑字段可改，保存后对不可编辑字段的修改被忽略 - 操作者: 普通用户
6. 管理员随时调整权限配置，该角色用户下次请求即按新权限过滤；禁用用户后其会话即时失效 - 操作者: 系统管理员

**规则关注点**：

| 规则 ID | 适用步骤 | 违反处理 |
|---------|----------|----------|
| BR-019-1 登录强制 | 4-5 | 未登录 401 / 重定向登录页 |
| BR-019-2 白名单制 | 2、5 | 未配置字段默认隐藏 |
| BR-019-3 可编辑以可见为前提 | 2 | 配置时自动约束 |
| BR-019-4 内置管理员不可删 | 1、6 | 删除操作拒绝 |
| BR-019-5 多角色取并集 | 3、5 | — |
| BR-019-6 后端序列化层过滤 | 5 | 数据不下发；写入忽略不可编辑字段不报错 |
| BR-019-7 生效范围 | 5 | 变更日志与对外 API 本期不叠加 |
| BR-019-8 新增默认隐藏 | 2 | 新字段/新域需显式授权 |

**依赖锚点**：

| 依赖 | 依赖类型 |
|------|----------|
| modeling（域/字段集） | 权限配置对象 |
| archive（档案列表/详情/编辑接口） | 过滤执行点 |
| REQ-005 场景2 | 需求承接（字段级粒度替代档案×操作粒度） |
