# 头脑风暴

## Part A：发散

### 角色维度
| 发现 | 处理 |
|------|------|
| 数据管理员、业务人员、系统管理员、数据管理者四个角色覆盖了核心使用场景 | 已覆盖 |
| **审计员**：需要独立的只读审计角色，专门查看操作日志和变更历史，不能触碰业务数据 | **新增**：审计角色 |
| **外部系统消费者**：通过API消费主数据，无需登录系统 | 已通过REQ-005的API开放覆盖 |

### 场景维度
| 发现 | 处理 |
|------|------|
| **主数据版本管理**：误操作或重复导入后需要回退到历史版本 | **新增**：数据版本与回滚 |
| **主数据合并/拆分**：如两个供应商实际是同一家，需要合并档案并保留历史 | **新增**：数据合并功能 |
| **字段变更后的存量数据处理**：给表新增字段后，已有记录的该字段值留空还是设默认值？现有记录是否需要回填？ | **新增**：存量数据处理策略 |
| **模型版本管理**：修改模型后（如删除字段），已有的档案记录如何处理？ | **暂不处理**（MVP后优化，建议第一阶段做字段禁用而非物理删除） |
| **数据归档/清理**：过期无用数据是归档还是物理删除？ | **暂不处理**（MVP后优化） |

### 规模维度
| 发现 | 处理 |
|------|------|
| **大表/大字段场景**：一张表50+字段时，表单分组展示和列表展示的交互性能 | 开发阶段关注性能，不影响功能设计 |
| **Excel大数据量导入**：单次导入数万行时的性能、校验超时、前端等待 | 开发阶段设计异步导入+进度通知 |

### 依赖维度
| 发现 | 处理 |
|------|------|
| **AI模型断连降级**：LLM API不可用时，AI相关功能（分类、语义规则、日报）需有降级方案 | **新增**：AI功能降级策略 |
| **通知渠道单一**：目前仅企业微信，其他渠道（邮件、短信）未覆盖 | **暂不处理**（可扩展设计，MVP专注企微） |
| **企微配置**：需要企业应用凭证、Robot Webhook等 | 运维阶段处理 |

### 反向维度（缺少这些会怎样）
| 发现 | 处理 |
|------|------|
| 没有数据版本 → 误操作后无法恢复，数据安全性不足 | 见"场景维度"新增 |
| 没有模型文档导出 → 团队协作和跨系统沟通困难 | **新增**：模型文档导出（PDF/Markdown） |
| 没有操作日志查询界面 → 审计需求无法满足 | 已由REQ-003（BR-007）覆盖，但需补充审计查询页面 |

## Part B：挖掘遗漏

### 角色遗漏
| 发现 | 新增 / 暂不处理 |
|------|-----------------|
| **审计员**：只读权限，可查看所有档案和操作日志，不可新增/修改/删除 | **新增**：审计角色进入REQ-005权限体系 |

### 流程遗漏
| 发现 | 新增 / 暂不处理 |
|------|-----------------|
| **模型变更对存量数据的影响**：新增字段→存量数据该字段填什么？修改字段类型→存量数据是否兼容？删除字段→存量数据怎么办？ | **新增**：存量数据处理策略（新增字段留空/默认值，类型变更做兼容检查，字段禁用而非删除） |
| **档案数据变更的审批流程**：用户未明确是否要审批 | 待用户确认（见下方追问） |

### 数据遗漏
| 发现 | 新增 / 暂不处理 |
|------|-----------------|
| **数据版本和变更追溯**：每次修改保留快照，支持查看历史版本和回滚 | **新增**：数据版本管理 |
| **模型文档导出**：将域、表、关系、字段定义导出为文档 | **新增**：模型文档导出 |

### 集成遗漏
| 发现 | 新增 / 暂不处理 |
|------|-----------------|
| **Webhook通知**：规则触发时可调用外部系统接口（如通知下游系统暂停消费问题数据） | **暂不处理**（MVP后优化） |
| **API调用统计**：API调用量、频率、错误率监控 | **暂不处理**（MVP后优化） |
